# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Material for a 90-minute plenary session, "AI en kwaliteitsmanagement in de zorg", at the Santeon-inspiratiedag (10 November 2026, Maasstad Ziekenhuis, Rotterdam). The audience is 60+ registered quality advisors and managers from all Santeon hospitals. They follow rules more than they explore, and they are unsure what AI can do for incident reporting. The goal is that they leave thinking "ik zou hier morgen mee kunnen beginnen". The tone is concrete and step by step, with no hype.

It is mostly content, not a software project. The only tooling is a small Vite server for presenting locally (see below). There is no build, linter or test suite. All user-facing content is in **Dutch** and uses Dutch patient-safety terms: VIM (Veilig Incident Melden), SAC-score, PRISMA, IGJ, calamiteit, SIRE, NEN 8009. Keep new content in Dutch.

## House style and language for audience material

Everything the audience sees or receives follows the rules below: the start page, the demo, the animation, slides, handouts and follow-up mail.

**Visual style: the Business Data Solutions stylebook** in `~/Projects/brand-project/stylebook/`. It is local and outside this repo (`shared.css`, `kleuren.html`, `typografie.html`, `voice.html`, `merk.html`). Read it before you design anything new. The decisions for this project are:
- **Palette:** warm black `#1a1a1a`, cream `#f5f0e6` / `#f0ebe0`, off-white page `#f9f8f4`, and greys `#4b5563` / `#6b7280` / `#e5e7eb`. Chartreuse `#d4db3e` (`accent`) is the only accent colour. Use it as the brand accent: primary buttons, the active menu item, progress and link underlines. Never use it as a text colour on a light background, and never put white text on it, because the contrast is too low. Text on yellow is always `#1a1a1a`.
- **AI marker:** anything the AI produces or does gets **warm black with chartreuse text or icon plus the Bot icon** (lucide `bot`), like the light of the lighthouse. Use it for the "AI-voorstel" label, follow-up questions, the OKF files the agent read, the judge score, the AI summary, and the AI stage and graph nodes in the animation. In the JSX, use `<Tag ai>` or `<AiMark />` (tokens `agent` / `agentInk`). In the HTML files, use the same Bot SVG. Rule-based fallback results get no AI marker. A yellow fill alone never means AI. Don't use a dashed pattern for AI: the stylebook reserves dashes for warnings.
- **Exception:** the SAC 1–4 colours (`#B23A2E`, `#D97A28`, `#D0A400`, `#2E8B72`) stay, because they encode severity, not brand.
- **Type:** the system font stack from the stylebook, with no webfonts. The atlas still loads Google Fonts. It is source material and keeps its own style.
- **Brand mark:** the lighthouse logo and "Business Data Solutions" written in full (never "BDS"). Keep it small and put it in the footer only, so that the session stays about care, not about the firm.
- **Form of address:** always **je / jij / jouw**, never "u". This is the stylebook rule, and it was chosen deliberately for this audience too.

**Language:** all Dutch content (outline, speaker notes, slides, UI text) must:
1. Follow ASD-STE100, applied to Dutch. Use short sentences (instructions at most 20 words, descriptions at most 25), one instruction per sentence, the active voice, one meaning per word and no ambiguity. `ste100-writer` holds the rules. Its dictionary is English, so apply its principles to Dutch.
2. Pass a language edit before anyone shares it: `redigeer-nederlandse-tekst`, or `taalredactie-publicatie` for a full publication pass with a report.
3. Contain no AI-speak: use `schrap-ai-taal` and run its `scripts/aitaal.py` on the file.

The stylebook voice rules also apply. Write plain Dutch, and replace an anglicism when a natural Dutch word exists. Use Dutch number notation: €2.500, 3,5, 90%. Domain terms stay as they are (VIM, SAC, PRISMA, Ask / Assist / Automate, OKF, data lake).

**Project skills** in `.claude/skills/` are copies of the user's own skills. Their source versions live elsewhere.
- `ontwerp-dia` was written for HAN lectures. Here "docent" means the speaker, "student" means a participant, and `college.html` means any slide deck. Its rule "no stage directions on a slide" applies: put directions in the speaker notes.
- `beoordeel-onderwijsontwerp` checks the session design (PAMS, KISS), for example the interactive segment.

## Running the presentation locally

```
npm install    # once
npm start      # Vite on http://localhost:5173, opens the start page
npx esbuild src/main.jsx --bundle --format=esm --outfile=/dev/null --log-level=warning   # syntax + import check of the demo
npm run build  # public version in dist/, then the leak check scripts/controleer-build.mjs
npm run preview  # serve dist/ the way GitHub Pages does: no proxy, no live AI
```

**Public copy on GitHub Pages:** https://businessdatasolutions.github.io/santeon-presentatie/. `.github/workflows/pages.yml` builds and deploys it on every push to `main` (and by hand via `workflow_dispatch`). Live AI works only on the local server; the public build has it off by design:
- The build never reads `.env` (`envDir: false` in `vite.config.js`), and CI has no `.env` at all. So the API key and `VITE_STEMTOOL_URL` cannot reach `dist/`.
- There is no proxy and no `/api/status`. Code that switches on `import.meta.env.DEV` shows the public variant: `src/main.jsx` rejects every Anthropic call without a network request (the demo falls back to `ruleBasedTriage`), shows the note "Openbare versie zonder live AI" and hides the per-card retry line (marked `data-live-fout` in the JSX; the attribute does nothing in the artifact); the start page status says the same and drops the retry button; `meedoen.html` shows no QR code ("Geen stemtool in de openbare versie") and keeps the hand-vote fallback.
- Only the pages in `PAGINAS` and the files in `STATISCH` (`vite.config.js`) are published. Never use a glob: confidential files sit in the root. When you add a page or a file the pages link to, add it there.
- **d3 declares `"sideEffects": false`.** `.transition()` and `.interrupt()` on a selection exist only through a side effect of d3-transition, so `vite build` drops them unless the script has `import "d3-transition";` (a direct dependency). Without it, the page works with `npm start` but breaks online: only the progress bar moves. Every script that uses either method has the import; a new one needs it too.
- `scripts/controleer-build.mjs` fails the build if d3-transition is missing from `dist/assets`, or if `dist/` contains `sk-ant-`, `/api/anthropic`, `/api/status`, `.run.app`, any value from a local `.env`, or a confidential file name. It never prints a value.

- `index.html` is the start page (design "Startpagina 1d" from Claude Design). Since 7 November it is also the presentation itself: the room sees it on the beamer, so it shows only what is relevant to the audience: no references to the outline, no stage directions, no "Zeg" label and no start instructions. Directions for the speaker belong in the outline. The AI-connection check and the order buttons ("Markering wissen", "Beginvolgorde herstellen") stay. A tag at the bottom of a tile is for the audience too ("stem met je telefoon", "pdf", "Engelstalig"); do not use it for the page type. It has a warm-black header with the AI-connection check and a timeline (one bar per block, width by minutes), and under it one row per block, with the parts as tiles in a grid. The check calls `/api/status`, which fetches `/v1/models/{DEMO_MODEL}`, so it costs no tokens. Tile types: a link tile (white, chartreuse ↗), a text tile (cream, a point the speaker makes, no link), and the demo tile with the AI marker (`.kaart.ai`; its `.rij.breed` spans two columns from 1000px). The speaker can drag blocks (by the number tile) and tiles (by the grip) into another order, or use the arrow keys. Dropping in the grid follows reading order: a tile lands on the cell under the pointer. The script then renumbers the blocks from 0, recalculates their clock times from `data-min` and redraws the timeline. A tile's number is block number + position (`2.3`); in "Extra" it is `+1`. `data-blok` links a tile to its block in the outline (`2b`); it is not shown on screen and does not change when you reorder. The order is stored in `localStorage` (`santeon-startpagina-volgorde-v1`). "Beginvolgorde herstellen" clears it. The header is sticky and becomes small (`header.klein`: one row with title and status, plus the timeline) once you scroll past its full height; it grows back only above 40px, so the jump does not flicker. **Where we are:** opening a tile, or clicking a text tile, marks it (`.rij.nu`, stored as `santeon-startpagina-nu-v1`). The timeline then shows a pin in that block, at the tile's position within the block; earlier blocks stay bright and later blocks are dimmed. "Markering wissen" clears it. When you add a part, give its `.rij` a unique `data-id` and a `data-blok`, and copy the `.kop` markup with an empty `.nr` (the script fills it).
- `demo.html` and `src/main.jsx` mount the demo. `main.jsx` rewrites `fetch` calls to `https://api.anthropic.com/` into `/api/anthropic/`. `vite.config.js` proxies those calls and adds `x-api-key` (from `.env`, as `ANTHROPIC-API-KEY` or `ANTHROPIC_API_KEY`) and `anthropic-version` on the server side.
- Keep local-only code out of `vim-okf-simulatie.jsx`, so it still runs unchanged as a claude.ai artifact. `DEMO_MODEL` in `vite.config.js` must match the model in the JSX.
- Never put the key in a `VITE_`-prefixed variable or the browser. Never start the server with `--host`: that would open the proxy, and thus the key, to everyone on the venue network.
- The hosted copy at https://witusj.github.io/vim-okf-simulatie/ is a separate, older deployment with no API key, so it shows only the fallback. Present from the local server.
- The atlas (`background-material/2026-07-01-ai-maturity-frameworks-visuals.html`) loads d3, rough.js and mermaid from pinned copies in `background-material/vendor/`. That makes it work offline and from `file://`. Don't go back to CDN URLs: the unpinned `d3.v7.min.js` URL changed version and its integrity hash then blocked d3.

## The demo artifacts

They share incident IDs and the house-style palette (see above): warm black and cream neutrals, the SAC 1–4 colours, chartreuse `#d4db3e` as the brand accent, and the AI marker (black + chartreuse + Bot icon). When you change incident text, outcomes or colours in one file, update the others.

### `vim-okf-simulatie.jsx`: the live demo (Deel 2)

A single-file React component (`export default function App`) that depends on `react`, `recharts` and `lucide-react`. Locally it is served through `demo.html` (see above).

The architecture follows the story the demo tells: **data lake → semantische laag/ontologie → OKF-kennisbundel → AI-triage-agent → rapportage**. Each stage is one panel (`LAYERS` drives the sidebar; `ArchPanel`, `LakePanel`, `OntoPanel`, `OkfPanel`, `AgentPanel`, `ReportPanel`).

- **Data:** `INCIDENTS` holds the fictional hospital "St. Machteld" free-text reports. `OKF` holds knowledge atoms keyed by filename (metadata plus a Markdown `body`). Two incidents are **deliberately flawed** and should not be "fixed". VIM-2026-0501 is incomplete and must trigger the ASK loop. VIM-2026-0505 is contradictory and must produce `escalatie: true`.
- **Agent pipeline (`agentTriage`):**
  1. An ASK/ANSWER loop. The agent may ask questions of `infoProviderAnswer`, a stateless oracle that answers only from the report text, up to `MAX_ASK_TURNS`. After that, an answer is forced.
  2. A verify-and-retry loop (`verifyTriage`, `MAX_VERIFY_RETRIES`) that checks the answer against the OKF runbook.
  3. `normalizeTriage`.
  
  `judgeRationale` (LLM-as-judge) runs separately from `AgentPanel`. `ReportPanel.genSummary` makes its own API call.
- **The prompt is built from a hard-coded subset of `OKF` keys** (the filter list in `agentTriage`, plus `metric-severity-assessment-code.md` in `verifyTriage`). Renaming an OKF atom means updating those references too.
- **Keep these in sync:** the JSON schema in the system prompt; the enums `SAC`, `CAT`, `PRISMA` and `BOUNDARY_CONDITIONS`; `normalizeTriage`; and `ruleBasedTriage`.
- **API calls** go straight to `https://api.anthropic.com/v1/messages` with no key header, using model `claude-sonnet-4-6` (hard-coded in `callClaudeJSON`, `callClaudeText` and `genSummary`). They only succeed in a host that proxies the API: the local Vite server or a claude.ai artifact.
- **Offline fallback:** any error in `agentTriage` falls back to the keyword-based `ruleBasedTriage`, which is flagged `_fallback` / `_error` in the UI, and an unreachable verifier does not block. This keeps the demo working offline on stage. Keep this behaviour.

### `vim-swimlane.html` (2b): the full VIM workflow as a swimlane

The Kansenkaart. It shows the full schema from `vim-workflow.excalidraw` (four routes, the endpoints A–E and the sources) as a speaker-paced swimlane, so the room sees that the speaker knows their process. It has no AI kansen and no AI marker. It loads `src/vim-swimlane.js` and `src/vim-swimlane.css` on top of `src/architectuur.css` (same keys, `#stap-N`, nav; `body.compact` makes the header small so the board gets the room). d3 draws five lanes (roles: zorgverlener en melder, afdeling/PVC, MIP-commissie, raad van bestuur en IGJ, kwaliteitssysteem) against five phase columns plus an endpoint column. Every step has its own layout (`indeling(focus)`). motion interpolates between layouts frame by frame (`meng`), so the lane you talk about grows and shows the full text (`lang`) while the others shrink to thin bars. A dot (the melding) walks the route of that lane; it is only visible between boxes, and the box it is in lights up. Steps: grid → route 1 → 2 → 3 → 4 → leren (the feedback loops light up) → endpoints → sources (large cards over the dimmed board). The content lives in `BANEN`, `VAKKEN`, `PIJLEN` and `BRONNEN` and is copied by hand from the Excalidraw schema: when you change that schema, update these too. Deliberate deviations: "Calamiteit?" uses the Wkkgz definition (death or serious harm), not the risicomatrix from the schema; the inspectorate is IGJ, not IGZ; the internal conversation notes and the international software sources are not shown. If text no longer fits, the console warns `Swimlane past niet`.

### `meedoen.html` (3b and the evaluation): the room votes with phones

The room sits in a theatre setup, so 3b has no group talk. Everyone votes on their own phone through the **stemtool** from the user's HAN lectures (repo `~/Documents/HAN/A-CLUSTER/a-cluster`, folder `stemtool/`: one Cloud Run service with Firestore, no login). Same keys, `#stap-N`, header and nav as above; it loads `src/meedoen.js` and `src/meedoen.css` on top of `src/architectuur.css`. Nine steps: QR → SAC vote on VIM-2026-0505 → what the agent does (AI marker, escalation reason) → the three safety questions one by one, each a "Weet je …?" question (A "Ja", B "Nee, maar ik weet wie het weet", C "Nee, en ik weet niet wie het weet") → the three side by side, with an accent line under the one with the most C → word cloud "wie vraag je morgen?" (functions, never names) → evaluation (stars; the numbers stay on the dashboard, never on the beamer).
- **Source of the questions:** `stemtool.json` in the repo root (college id `santeon`, with a `thema` in the house style). The a-cluster repo reads it through `stemtool/gastbronnen.txt`; `verzamel.py` refuses to deploy if that path is missing. `STAPPEN` (the headings) and `OPTIES` in `meedoen.js` copy the questions and options: change them together. Do not change a `code` or `sleutel` once there are answers in Firestore.
- **The service URL stays out of git and out of the public build.** It is `VITE_STEMTOOL_URL` in `.env`, because the dashboard has no login and this repo is public. The QR code is generated in the browser (npm `qrcode`) and points to `/santeon/mee`, not `/mee`, so an open HAN question cannot take over the phones. Press D on the page to open the dashboard (`/docent/santeon`).
- **No mock results, ever.** Question and result share a step, so example bars would anchor the voters. Without answers the bars stay empty; without a connection the page says "steek je hand op", and the speaker notes give the hand-vote fallback. This deliberately differs from the HAN decks, which keep a mockup.
- `TEGENSTRIJDIG` in `src/meldingen.js` holds VIM-2026-0505: text as in the JSX `INCIDENTS`, escalation reason as in the animation `CASES`.
